# Оплата в BuildPath: провайдер и модель

Статус: 11 ноября 2026. Нормативные требования — в PRODUCT_REQUIREMENTS.md и TECHNICAL_SPECIFICATION.md; здесь — решение по провайдеру и что уже сделано.

## Модель

- **Баланс проекта (предоплата).** Запросы к ИИ оплачиваются из баланса проекта; владелец пополняет его картой. Режим включает персонал в админке («Project balance»); по умолчанию выключен — тогда запросы только считаются в смете. Расход считается с момента включения.
- Деньги зачисляются **только после подписанного уведомления провайдера**, один раз, при совпадении суммы и валюты. Возврат на сайт после оплаты сам по себе ничего не зачисляет.
- **Специалисты** (раздел 29 STAGE_WORK_MODEL): начисление создаётся при приёмке этапа. Владелец может заплатить «напрямую» и отметить это, или **оплатить через BuildPath**: платит всю сумму картой, деньги поступают платформе (статус «оплачено в BuildPath»), сотрудник BuildPath переводит специалисту его часть на IBAN и записывает номер перевода (статус «переведено специалисту»). Комиссия BuildPath — настройка персонала, 0–30 %, по умолчанию 0; фиксируется в момент оплаты и удерживается из части специалиста. **Автоматических переводов нет**: деньги уходят только руками сотрудника, каждый просмотр счёта и каждый перевод записываются в аудит.

## Сравнение провайдеров для юрлица в Казахстане

| | Freedom Pay | TipTopPay (бывший CloudPayments Kazakhstan) | Kaspi Pay | Stripe |
|---|---|---|---|---|
| Приём картой онлайн | да | да | оплата в приложении Kaspi | — |
| Публичная документация API | да: Merchant API (создание платежа, уведомление о результате), выплаты на карту и IBAN | да: виджет и API | API для партнёров по договору (QR); без договора — только платёжная ссылка с ручной проверкой | — |
| Выплаты (для специалистов) | есть в API | уточнять | нет в открытом виде | — |
| Доступность для компании из РК | да | да | да (ИП и ТОО) | нет: Stripe не работает с компаниями, зарегистрированными только в Казахстане |

Тарифы и комиссии у всех — по договору, их нужно запросить у менеджера.

**Решение для первой версии:** Freedom Pay — открытая документация на приём платежей и выплаты, что понадобится для оплаты специалистов. Адаптер сделан так, что можно добавить второго провайдера (например, Kaspi Pay после партнёрского договора) без изменения модели.

## Что сделано

- Адаптер Freedom Pay по документации Merchant API: `init_payment.php`, уведомление `result_url` с подписанным XML-ответом, подпись MD5 по правилу «имя скрипта; значения по алфавиту ключей; секретный ключ». Проверен юнит-тестами и локальным сервером-двойником; **с боевым кабинетом Freedom Pay ещё не проверялся** — нужен тестовый мерчант.
- Тестовая страница оплаты для разработки (`PAYMENTS_PROVIDER=mock`), запрещена в production.
- Карточка «Баланс проекта» у владельца, переключатель режима и минимальная сумма в админке, ответ `402 PROJECT_BALANCE_LOW` с понятным объяснением.

## Возвраты и квитанции (работают в тестовом режиме)

- **Возврат остатка баланса.** Владелец просит вернуть часть пополнения, которая ещё не потрачена на ИИ. Сумма сразу откладывается и не тратится, пока сотрудник не решит; заявку можно отозвать. Сотрудник возвращает или отказывает (с объяснением владельцу), каждое решение — в аудите.
- **Возврат оплаты специалисту.** Пока деньги за специалиста лежат на платформе и не переведены ему, сотрудник может вернуть их владельцу (например, после спора) с объяснением.
- С тестовым провайдером (`mock`) возврат проходит сразу. С настоящим провайдером BuildPath **не вызывает API возврата, который не проверен на боевом кабинете**: сотрудник делает возврат в кабинете провайдера и записывает его номер.
- **Квитанция** у каждого оплаченного пополнения и оплаты специалисту: номер, позиции (работа специалиста, комиссия BuildPath), возвраты, номер платежа у провайдера. Это подтверждение оплаты, **не фискальный чек**; у тестовых платежей это написано на квитанции.

## Если проект будет глобальным

Freedom Pay и Kaspi выбраны для первого рынка — Казахстана: там карты и Kaspi у всех, а юрлицо из РК не может подключить Stripe. Для работы в других странах нужен другой провайдер; модель (баланс, начисления, возвраты, квитанции) от этого не меняется — меняется адаптер.

| | Stripe (с Connect) | Paddle / Lemon Squeezy (merchant of record) |
|---|---|---|
| Приём оплаты по миру | да | да |
| Налоги других стран (VAT, sales tax) | считает Stripe Tax, платит и отчитывается компания | берёт на себя провайдер — он юридически продавец |
| Оплата специалистов через платформу (маркетплейс) | да, это назначение Stripe Connect | нет: правила Paddle запрещают продукты, через которые продают третьи лица (маркетплейсы) |
| Что нужно | компания в стране, где работает Stripe | компания почти в любой стране, проверка продукта |

Вывод: если оплата специалистов через BuildPath остаётся частью продукта, для глобального запуска подходит Stripe с Connect (понадобится компания в поддерживаемой стране). Если специалистам платят напрямую, а BuildPath продаёт только баланс для ИИ, проще merchant of record вроде Paddle. Kaspi остаётся вариантом только для Казахстана.

## Открытые вопросы перед приёмом денег за специалистов

- Принимая оплату за работу третьих лиц и перечисляя её им, платформа может считаться платёжным агентом или посредником. Нужно уточнить требования законодательства РК (договор поручения или агентский договор, налоги, отчётность) и закрепить это в пользовательском соглашении. До этого режим «оплатить через BuildPath» стоит включать только после консультации.
- Удерживать ли налоги со специалистов-физлиц, или работать только с ИП и самозанятыми.
- Автоматические выплаты через API провайдера (у Freedom Pay они есть) — после договора на выплаты.

## Что нужно от владельца платформы

1. Заключить договор с Freedom Pay, получить `merchant id` и секретный ключ, указать адрес уведомлений `https://<API>/api/v1/payments/freedompay/result`.
2. Пройти тестовый платёж в тестовом режиме (по умолчанию `FREEDOMPAY_TESTING_MODE=true`).
3. Решить вопрос фискальных чеков (онлайн-касса). Сейчас формируется только подтверждение оплаты, не фискальный чек.
4. Для глобального запуска — выбрать между Stripe Connect и merchant of record (раздел выше).
