# BuildPath — статус реализации

Срез на 9 ноября 2026 года. Это фактический статус кодовой базы, а не обещание готовности к production. Полный порядок работ задан в [IMPLEMENTATION_ROADMAP.md](IMPLEMENTATION_ROADMAP.md).

## Кратко

Есть рабочий путь конструктора по этапам для одностраничного сайта и сайта компании: от цели до собранной и проверенной страницы, которую можно скачать. ИИ выполняет этапы по инструкциям владельца, без ИИ работают формы и шаблоны. Готовый сайт можно опубликовать на поддомен BuildPath и получать заявки с формы в Telegram или на почту. На этап можно пригласить специалиста: он направляет ИИ и отправляет результат на приёмку, видя только свой этап. Этапы можно вести и в Telegram: в боте кнопками или в Mini App. Отдельно работает инструмент сверки сайта с требованиями и макетами. Развёртывание отложено до завершения разработки.

## Конструктор по этапам (модель из STAGE_WORK_MODEL.md, срез 1)

| Возможность | Статус | Границы |
|---|---|---|

| Старт с любого этапа и свои материалы | Готово с ограничениями | Вставка текста; загрузка файлов и анализ репозитория в этапах пока нет. |
| Цикл работы с ИИ на этапе | Готово с настройкой | Нужны `BUILDER_AI_OPENAI_API_KEY` и `BUILDER_AI_OPENAI_MODEL`. Проверено на совместимой заглушке; с реальной моделью качество текстов не проверялось. Без ИИ — формы и шаблоны. |
| Версии, правила, защита ручных правок | Готово | Неизменяемые версии с происхождением; правила этапа и проекта. |
| Приёмка, зависимости, «Нужно проверить» | Готово | Личный режим владельца. Командные политики согласования не реализованы. |
| Сборка сайта и проверки | Готово с ограничениями | Одна страница без скриптов; проверки содержимого, не полный quality gate. |

Пересохранение в WebP с удалением метаданных. Проверено локально с `UPLOAD_MALWARE_SCAN=disabled`; с работающим ClamAV не проверялось. Кадрирования и галерей нет. |
| Результат на любом этапе | Готово | `project.md`, `project.json`, `site.html`. |
| Публикация на поддомен BuildPath | Готово с настройкой | Отдельный сервер сайтов (`npm run start:sites`). Для production нужны wildcard DNS и TLS для `*.SITES_BASE_DOMAIN`. Проверено локально на `*.localhost`. Свой домен не реализован. |

| Уведомления о заявках | Готово с настройкой | Telegram-бот (токен, имя, секрет webhook) и email через Resend. Проверено на заглушке Bot API; с реальным ботом не проверялось. |
| Специалисты на этапе | Готово с ограничениями | Ведущий и консультант, приглашение по ссылке с привязкой к почте, доступ только к своему этапу и его входам, лимит ИИ, приёмка и возврат на доработку, предложения консультанта. Нет тонкой настройки доступа, личных плейбуков, каталога специалистов и оплаты. |
| Этапы в Telegram (бот и Mini App) | Готово с настройкой | Проекты и этапы кнопками, просьбы к ИИ текстом, сборка, приёмка с подтверждением, отправка и возврат, предложения; вход в Mini App по initData. Нужен бот с webhook и HTTPS-адрес приложения. Проверено на заглушке Bot API; голосовые не распознаются. |

## Проверка сайта и макета

| Возможность | Статус | Границы |
|---|---|---|
| Аккаунт, workspace и проекты | Частично готово | Регистрация, подтверждение email, сессии, список и создание проектов. Полный autosave/activity workflow и управление участниками не реализованы. |
| Анализ публичного сайта | Готово с ограничениями | Same-origin crawler с лимитами страниц, глубины, размера ответа, редиректов и времени. |
| Загрузка дизайнов по страницам | Готово | PNG/JPEG; приватное хранилище, проверка типа, checksum и malware scan. |
| Импорт кадра Figma | Готово с настройкой | Нужны OAuth-параметры и ключ шифрования; пользователь явно выбирает файл/кадр. |
| Сравнение сайта с макетом | Готово с ограничениями | Снимок Chromium, side-by-side/overlay/wipe, пиксельное отличие и регионы. Это не семантическая оценка соответствия. |
| ИИ-сверка | Готово с настройкой | Необходим OpenAI API key/model; результаты — предложения, не автоматическое одобрение ТЗ или backend. |
| Проверка ТЗ | Частично готово | Ручной checklist, статусы и доказательства. ИИ не выставляет статус требования. |
| Backend/API | Ограниченный probe | Только пользовательские GET/HEAD проверки с ожидаемым HTTP-статусом и необязательным JSON-path. Это не полный интеграционный или security-тест. |
| DOM/доступность | Ограниченный аудит | Эвристические счётчики и признаки; не полноценная WCAG-проверка. |
| Отчёты | Готово | JSON, автономный HTML, печать в PDF; включает покрытие, сигналы, страницы и ограничения. |
| Каталог и администрирование | Готово с ограничениями | Staff sign-in; каталог возможностей; управление версиями quality profiles; журнал аудита только для super admin и operations auditor с фильтрами, лимитом окна 90 дней и безопасной пагинацией. Управление данными проектов и release controls не реализованы. |
| Quality profiles и gate | Частично готово | Staff API и admin UI для профилей, черновиков и истории. Глобальная default-версия фиксируется при создании review. Gate оценивает покрытие ТЗ, пользовательские API probes, доступность/SEO эвристики, HTTPS и выбранные security headers, навигационные timing/resource метрики. Нет vulnerability/dependency сканирования, полноценного Lighthouse/Core Web Vitals и блокировки публикации. |

## Сквозной продукт

| Этап roadmap | Статус |
|---|---|
| 0. Репозитории, запуск, схема, миграции, CI, OpenAPI | Частично готово; capability manifest и отдельные admin auth endpoints описаны в OpenAPI. |
| 1. Аккаунты и проекты | Частично готово; нет полного dashboard lifecycle, команд и activity log. |
| 2. Требования и analysis-only | Частично готово только в части URL-сверки; интервью, route proposal и анализ архива/репозитория/документов не готовы. |
| 3. Генерация сайта и preview | Не реализовано. |
| 4. Команда, approvals, версии | Частично: специалисты на этапе, приёмка и возврат на доработку, версии; общих команд проекта и политик с несколькими проверяющими нет. |
| 5. Telegram bot/Mini App | Частично: бот ведёт этапы и присылает уведомления, Mini App входит по initData; голос и групповые чаты не поддерживаются. |
| 6. Hosting, production publish, rollback | Частично: публикация на поддомен BuildPath, обновление до новой принятой сборки и снятие с публикации; свой домен и внешние хостинги не реализованы. |
| 7. Дополнительные возможности | Частично: реализуется самостоятельная сверка сайта; другие расширения зависят от этапов 0–6. |

## Готовность к запуску (10 ноября 2026)

| Что | Статус | Где |
|---|---|---|
| Запуск на одном сервере (Docker, HTTPS, все сервисы) | Подготовлено, не проверено на сервере | `builder-back/deploy/README.md`. Образы в среде разработки не собирались: там нет Docker. Отдельно проверены production-сборки front/admin, работа через один адрес с `/api`, миграции на пустой базе. |
| Сертификаты для сайтов клиентов | Подготовлено | Выпуск по запросу только для опубликованных сайтов (проверка на сервере сайтов). Лимит Let's Encrypt ~50 новых сайтов в неделю; дальше — wildcard через DNS. |
| Резервные копии | Готово | Ежедневно, проверка целостности, хранение 14 дней, зашифрованная копия в облако через rclone. Восстановление проверено, в том числе из зашифрованной копии. Копирование в облако не проверялось. |
| Отчёты об ошибках | Готово с настройкой | Sentry или GlitchTip через `SENTRY_DSN`; без cookie, тел запросов и данных пользователей. Отправка проверена на тестовом приёмнике. |
| Оферта и политика конфиденциальности | Черновики | `docs/legal/`. Нужна проверка юристом. |
| Согласие при регистрации | Не реализовано | Нужна отметка о согласии с офертой, политикой и трансграничной передачей с фиксацией времени и версии. Делать после проверки документов юристом. |
| Удаление аккаунта самим пользователем | Не реализовано | Пока только по письму. |

## Следующие необходимые работы

1. Расширить baseline до проверки уязвимостей, устойчивых performance budgets/Core Web Vitals и связать доказательства с release readiness; проектную публикацию пока не блокировать фиктивной проверкой.
2. Добавить project-level выбор quality profile и фиксировать выбранную активную версию в новых review.
3. Подготовить analysis-only источники для ZIP/репозитория/документов и сохраняемый отчёт с неизученными областями.
4. Затем закрывать этапы продукта вертикально: интервью и требования → SiteSpec/детерминированная генерация → команда и approvals → deploy provider и quality gate.

## Ограничения текущей готовности

Рабочая сверка не означает готовность BuildPath как полного builder-продукта. Перед включением реальных пользователей потребуются environment configuration, миграция AI-поля, проверка изолированного worker egress, расширение quality evidence и подключение gate к release readiness, дальнейшее production-hardening staff boundary для admin, operational monitoring и end-to-end проверка развёрнутой инфраструктуры.
