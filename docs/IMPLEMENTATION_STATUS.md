# BuildPath — статус реализации

Срез на 9 ноября 2026 года. Это фактический статус кодовой базы, а не обещание готовности к production. Полный порядок работ задан в [IMPLEMENTATION_ROADMAP.md](IMPLEMENTATION_ROADMAP.md).

## Кратко

Есть рабочий путь конструктора по этапам для одностраничного сайта и сайта компании: от цели до собранной и проверенной страницы, которую можно скачать. ИИ выполняет этапы по инструкциям владельца, без ИИ работают формы и шаблоны. Специалисты, Telegram и публикация пока не реализованы. Отдельно работает инструмент сверки сайта с требованиями и макетами. Развёртывание отложено до завершения разработки.

## Проверка сайта и макета

| Возможность | Статус | Границы |
|---|---|---|
| Аккаунт, workspace и проекты | Частично готово | Регистрация, подтверждение email, сессии, список и создание проектов. Полный autosave/activity workflow и управление участниками не реализованы. |
| Анализ публичного сайта | Готово с ограничениями | Same-origin crawler с лимитами страниц, глубины, размера ответа, редиректов и времени. |
| Загрузка дизайнов по страницам | Готово | PNG/JPEG; приватное хранилище, проверка типа, checksum и malware scan. |
| Импорт кадра Figma | Готово с настройкой | Нужны OAuth-параметры и ключ шифрования; пользователь явно выбирает файл/кадр. |
| Сравнение сайта с макетом | Готово с ограничениями | Снимок Chromium, side-by-side/overlay/wipe, пиксельное отличие и регионы. Это не семантическая оценка соответствия. |
| ИИ-сверка | Готово с настройкой | Необходим OpenAI API key/model; результаты — предложения, не автоматическое одобрение ТЗ или backend. |
| Проверка ТЗ | Частично готово | Ручной checklist, статусы и доказательства. ИИ не выставляет статус требования. |
| Backend/API | Ограниченный probe | Только пользовательские GET/HEAD проверки с ожидаемым HTTP-статусом и необязательным JSON-path. Это не полный интеграционный или security-тест. |
| DOM/доступность | Ограниченный аудит | Эвристические счётчики и признаки; не полноценная WCAG-проверка. |
| Отчёты | Готово | JSON, автономный HTML, печать в PDF; включает покрытие, сигналы, страницы и ограничения. |
| Каталог и администрирование | Готово с ограничениями | Staff sign-in; каталог возможностей; управление версиями quality profiles; журнал аудита только для super admin и operations auditor с фильтрами, лимитом окна 90 дней и безопасной пагинацией. Управление данными проектов и release controls не реализованы. |
| Quality profiles и gate | Частично готово | Staff API и admin UI для профилей, черновиков и истории. Глобальная default-версия фиксируется при создании review. Gate оценивает покрытие ТЗ, пользовательские API probes, доступность/SEO эвристики, HTTPS и выбранные security headers, навигационные timing/resource метрики. Нет vulnerability/dependency сканирования, полноценного Lighthouse/Core Web Vitals и блокировки публикации. |

## Сквозной продукт

| Этап roadmap | Статус |
|---|---|
| 0. Репозитории, запуск, схема, миграции, CI, OpenAPI | Частично готово; capability manifest и отдельные admin auth endpoints описаны в OpenAPI. |

| 2. Требования и analysis-only | Частично готово только в части URL-сверки; интервью, route proposal и анализ архива/репозитория/документов не готовы. |
| 3. Генерация сайта и preview | Не реализовано. |
| 4. Команда, approvals, версии | Не реализовано. |
| 5. Telegram bot/Mini App | Не реализовано. |
| 6. Hosting, production publish, rollback | Не реализовано. |
| 7. Дополнительные возможности | Частично: реализуется самостоятельная сверка сайта; другие расширения зависят от этапов 0–6. |

## Следующие необходимые работы

1. Расширить baseline до проверки уязвимостей, устойчивых performance budgets/Core Web Vitals и связать доказательства с release readiness; проектную публикацию пока не блокировать фиктивной проверкой.
2. Добавить project-level выбор quality profile и фиксировать выбранную активную версию в новых review.
3. Подготовить analysis-only источники для ZIP/репозитория/документов и сохраняемый отчёт с неизученными областями.
4. Затем закрывать этапы продукта вертикально: интервью и требования → SiteSpec/детерминированная генерация → команда и approvals → deploy provider и quality gate.

## Ограничения текущей готовности

Рабочая сверка не означает готовность BuildPath как полного builder-продукта. Перед включением реальных пользователей потребуются environment configuration, миграция AI-поля, проверка изолированного worker egress, расширение quality evidence и подключение gate к release readiness, дальнейшее production-hardening staff boundary для admin, operational monitoring и end-to-end проверка развёрнутой инфраструктуры.
